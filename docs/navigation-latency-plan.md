日期：2026-10-30；实施前落档。真实位置是 boostCleaner 的 GlobalConfigNew.kt 中 object 名称。先拆分首查/热查询的定义解析、Java 和 Kotlin 引用耗时，再按证据减少重复和串行等待。候选筛选仅缩小编译范围，返回结果仍经语义确认；模型、文档及跨文件变化必须失效，取消/结果边界保持有效。

阶段：N0 日志基线 → N1 瓶颈优化 → N2 正确性和调试耗时 → N3 发布包与原生覆盖验收。不新增依赖、不改 SDK 权限、不写业务文件、不推送远程。首查与连续查询分别记录，任何缓存有界且仅在当前分析快照有效。

具体计划与后续证据见宿主 `docs/engineering/2026-10-30-language-navigation-latency-plan.md`。N0 正在测量，暂不声明性能收益。

## N0–N2 记录

- 已用原生客户端和独立适配器复现指定位置。原生定义 33ms、引用 4765ms，返回 69；独立冷语义样本约 10.3 秒，连续查询 224–356ms。耗时主要在首次编译使用方语义绑定，不是弹窗 DOM。
- .4 组件在 indexing 阶段完成所选模块依赖闭包的语义准备，合并 BindingContext 时去重；该准备本机 boostCleaner 样本 18.9 秒，增加索引阶段工作，保持原 2×2GiB JVM 上限。Java/Kotlin 引用分支并行，任一失败取消并排空另一分支，仍经语义确认和依赖图过滤。
- 编译器 KAPT 元数据仅在当前完整源码摘要与 ABI revision 一致时，提供直白 class/object/interface 的类名范围；通过已知编译器声明起点映射文本，绝不据同名猜引用。复杂语法或缺少元数据回退 Kotlin 服务。定义至引用的一次性交接缓存最多 16 条/256KiB/2 秒，绑定模型、分析 revision 和文档版本；不持久化结果。
- 对已打开 Kotlin 类预备 Java 声明锚点，有界 128 条、同代产物共享查询，任一订阅者取消不取消其他订阅者，模型结束整体取消；过时结果拒绝入缓存。打开缓冲区仅等待覆盖层同步，不等待额外 JVM 预热；真实查询按需要等待自己的后端。
- 私有新增/删除/重命名、未保存/保存提升、同名隔离和跨 Java/Kotlin 类/方法引用九项通过。插件单测 22 项通过。给定对象在索引就绪后首查 495ms、连续 160–190ms，仍 69 个结果，业务源码未改。后续以接受包和原生实测为最终依据。
- 新增各阶段耗时沿既有调试开关记录，不含源码或符号。
